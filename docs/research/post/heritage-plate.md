## 0. 한눈에 (사용자에게 전할 말)

- 「유산」 단추는 **메뉴가 없는 단추 하나**다. 누르면 조사구역이 속한 시·군을 판정하고, 확인 창을 한 번 띄우고, 국가유산 인트라넷(`intranet.gis-heritage.go.kr`)에 로그인해 **그 시·군 전체의 6종 자료**를 ZIP 으로 받는다. 반경으로 받지 않는다. 받은 뒤 **조사구역 주변 5 km 안에 걸치는 도형만 남기고** 지도의 「참조 지도」 그룹에 올린다.
- 「주변 500m」는 이 단추의 일이 아니다. 별도 단추 「버퍼」의 하위 막대(「주변유적경계 ›」)에서 500m·1000m 경계선을 그린다. 유산 도형을 500 m 로 자르지 않는다.
- 도면(조판)에는 **「주변유적 분포도」라는 전용 도면 종류가 없다.** 도면 4종(조사구역도·유적위치도·유구배치도·개별유구실측도) 어느 것에서나, 지도에 켜 둔 유산 레이어가 자동으로 도면 지도에 들어가고, **조사구역에서 500 m 이내인 유적에만 번호 배지(원 안의 숫자)를 붙여 범례에 「번호 + 유적명」 줄을 만든다.** 500 m 밖 유적은 색으로만 그려지고 번호·범례 줄이 없다.
- 도면 안에 「주변유적 표」는 없다. 표(연번·유적명·방향·거리…)는 엑셀 내보내기와 한글(HWP) 보고서 쪽에만 있다.
- 기존 메모 중 고칠 것: 단추 설명문과 서약서 안내문은 「받은 자료는 조사폴더 안에만 둡니다」라고 하지만, 실제로 ZIP·압축 해제본·진단 기록은 **로컬 앱 데이터 폴더**에 놓이고 조사폴더에는 **서약서 영수증 하나만** 남는다 (3.2절). 이 점은 `docs/DOWNLOAD_FLOWS.md` 427-430행이 이미 맞게 적고 있으니 그 문서는 그대로 두면 된다. `docs/NETWORK_ACCESS.md` 의 「재시도가 끝없이 계속」(556행)도 코드와 맞다 (5, 10, 20, 30, 30… 초, 아래 2.6절).

### 1.4 두 번째 누름
- 전용 처리 `not in the source`. 창은 재사용된다 (`MainWindow.cpp:3124-3126`), `start()` 는 먼저 `stop()` 을 부른다 (`app/KaHeritageBrowser.cpp:571-572`). 시·군 판정과 확인 창부터 다시 한다.

## 2. 내려받기

### 2.1 어디에서 / 무엇을
- 사이트 `https://intranet.gis-heritage.go.kr/`, 로그인 주소 `…/user/checkNet.do` (`core/HeritageIntranetFlow.cpp:86-92`). 다운로드 화면 `/user/data/heritageDownload.do?pageMenuId=DAT010010`, 목록 `/user/data/heritageDownloadList.do`, 전체받기 `/user/data/heritageDownload/downloadFilesAll.do` (`:203-213`).
- 방식: 앱 안에 숨겨 둔 **내장 웹브라우저(QWebEngine)** 가 사이트 화면을 사람처럼 조작한다. 프로필 이름 `ka-heritage`, 로그인 쿠키는 디스크에 쓰지 않는다 `NoPersistentCookies` (`app/KaHeritageBrowser.cpp:297-317`). 기본은 화면을 숨기고 「상세 보기」 단추로 펼친다 (`:269-283`).
- 요청 단위: **시·군 하나씩** (시·도 + 시·군·구를 사이트 폼에 넣고 검색). 반경·좌표로 요청하지 않는다. 이웃 시·군을 체크했으면 한 시·군이 끝난 뒤 다음 시·군을 차례로 요청한다 (`app/KaHeritageBrowserPlan.cpp:38-64`). 화면 문구 「전국 자료는 받지 않습니다」(`KaHeritageSetupDialogs.cpp:196-197`).
- 자료 종류 6종, 사이트 탭 코드 (`core/HeritageStyle.cpp:26-33`, 지정유산의 `S` 는 `HeritageIntranetFlow.cpp:247-248`): 지정유산(S) · 현상변경허용기준(P) · 매장유산유존지역(B) · 문화유적분포지도(U) · 지표조사구역(R) · 발굴조사구역(E). 자료마다 사이트의 `changeTab(코드)` 를 부르고 (`:245-261`), 시·도/시·군 칸을 채워 값이 폼에 남았는지 다시 확인한 뒤 「검색」, 결과 건수를 읽고 「전체다운로드」 단추를 **한 번** 누른다 (`KaHeritageBrowser.cpp:1003-1255`).
- 받는 형식: **ZIP**. ZIP 안의 파일 이름은 CP949 라서 풀 때 `CPL_ZIP_ENCODING=CP949` 를 건다 (`core/HeritageImport.cpp:173-185`). 안에는 SHP 묶음(.shp .shx .dbf .prj, 있으면 .cpg)이 여러 개 있다. 예: 지정유산 ZIP → 「국가지정유산 · 시도지정유산 · 국가등록문화유산 · 시도등록문화유산 · 국가지정유산보호구역 · 시도지정유산보호구역」 (`:232-235`, 2026-09-12 실제 파일로 확인했다고 주석에 있음).
- 서버가 ZIP 을 만드는 시간은 주석에 「측정 42~115초」 (`KaHeritageBrowser.cpp:860-861`), 화면에 「보통 40~120초」.

### 2.2 로그인 (값은 적지 않음, 이름만)
- 저장: 아이디는 설정 파일 `heritage-account.ini` 의 키 `heritage/username` (평문), 비밀번호는 `KaSecretStore` 의 `heritage` 묶음 (설치본은 Windows DPAPI, 포터블은 `password_portable`, `core/HeritageIntranetSettings.cpp:14-18, 26-27, 93-98`). 파일 위치는 `KaPortableRuntime::userConfigDir()`. 계정이 없을 때만 번들 `config/heritage-local.ini` 를 읽는다 (`:30-34, 42-57`). 로그에는 「계정 없음 / 계정 설정 미완료 / 저장된 계정 사용」 셋 중 하나만 남긴다 (`:64-70`).
- 순서 (`KaHeritageBrowser.cpp:896-948`): ① `loginProbeScript` 로 이미 로그인됐는지(화면에 「로그아웃」 글자) 본다 → 되어 있으면 「이미 로그인되어 있습니다.」 ② 아니면 `loginScript` 가 사이트의 `#userId`·`#pwd` 칸에 값을 넣고 **사이트 자신의 `goLogin()` 을 부른다** (비밀번호는 사이트 스크립트가 RSA 로 암호화하므로 앱이 평문으로 POST 하지 않는다, `core/HeritageIntranetFlow.cpp:135-148`). ③ 결과 `submitted` 면 「로그인 결과를 기다리는 중입니다.」 단계로 넘어간다.
- 로그인 스크립트의 본문(비밀번호 포함)은 로그에 남기지 않고 결과만 남긴다 (`KaHeritageBrowser.cpp:658-665`, 요청 기록도 `redactRequestLine`, 로그인 요청 본문은 적지 않음 `:436-439`).

### 2.3 로그인이 거절되면 (재시도하지 않는다)
- 「튜토리얼 닫기」 단계에서 로그인 칸이 아직 보이면: 8 틱(약 5.6 초, 틱 700 ms `:103`) 넘게 그러면 `fail("로그인이 되지 않았습니다. 아이디·비밀번호를 확인해 주세요.")` (`:927-932`). 로그인 제출(`goLogin()`)은 `submitted` 를 받는 순간 한 번 하고 단계가 넘어가므로 **같은 계정으로 두 번째 제출을 하지 않는다**.
- 그 밖: 로그인 화면에 `goLogin` 이 없으면 「로그인 화면이 바뀌었습니다(goLogin 없음).」 (`:910-913`), 스크립트 오류면 「로그인 중 오류가 났습니다: …」 (`:914-917`). 모두 `fail()`.
- `fail()` (`:445-477`)은 진행을 멈추고 이어서 받을 이웃 시·군도 **받지 않고** 「멈춰서 받지 않은 시·군: …」 을 남기며, 사이트가 보낸 요청 목록을 파일로 저장한 뒤 상태줄/알림 「주변유적 받기」 로 알린다. 재시도 예약은 하지 않는다.
- 주의: 재시도 논리는 **「내려받기」 단계 안에서만** 돈다 (`scheduleDownloadRetry` 는 `m_stage != Download` 면 바로 돌아감, `:504-507`). 그러나 한 번의 재시도는 `reopenDownloadSession` 으로 **공식 화면을 처음부터 다시 열어 로그인부터 다시 한다** (`:533-564`). 즉 서버가 비정상 파일을 계속 주면 계정으로 로그인이 반복될 수 있다. 그 로그인이 거절되면 위 8틱 규칙으로 멈춘다.

### 2.4 서약서
- 「국가유산자료 다운로드」(사이트의 `showAgreePopup()`)를 열면 「서약서에 동의」 체크 + 「확인」 을 자동으로 누른다 (`HeritageIntranetFlow.cpp:215-243`, `KaHeritageBrowser.cpp:975-1002`). 동의가 일어나면 시각과 서약서 원문을 `agreementAccepted` 로 넘겨 영수증 파일로 저장한다 (3.2절). 창 알림: 「서약서에 자동 동의했습니다. 원문은 조사폴더 주변유적/receipts 에 남습니다.」 + 「서약 요지(원문 그대로): …」 (`core/HeritagePledge.cpp:49-73`).
- 사이트가 띄우는 알림창(`alert`)은 내용을 남기고 닫고, `confirm` 은 「계속」, 입력창(`prompt`)은 값을 지어내지 않고 취소한다 (`KaHeritageBrowser.cpp:119-132`).

## 3. 받은 뒤 처리

### 3.1 종류마다 바로 지도에 올린다
한 종류의 파일이 검증되면 즉시 `importHeritageDataset` (`MainWindow.cpp:3135-3140, 3194-3225`) → `HeritageImport::loadDataset` (`core/HeritageImport.cpp:159-337`). 여섯 종을 다 기다리지 않는다. 올린 뒤 상태줄 「%1 %2곳을 올렸습니다.」(`:3220`), 모두 끝나면 창을 닫고 「주변유적 자료 처리를 마쳤습니다. 받은 자료는 「참조 지도」에 있습니다.」 (`:3143`). 올리기 실패는 그 종류만 `rejectDataset` (재시도 가능이면 2.6절 재수신, 아니면 멈춤).

### 3.2 어떤 도형이 남나
- 조사구역(`survey_area` 레이어들)의 합집합을 **5 km 버퍼** (`core/SurveyScopeClip.h:15` `kRadiusMeters = 5000.`, `.cpp:19-29, 70-73`)로 넓힌 범위와 **겹치는(intersects) 도형만 남기고 나머지는 삭제**한다 (`SurveyScopeClip.cpp:75-132`, 호출 `HeritageImport.cpp:247`). 잘라내지는 않고 도형 통째로 남긴다 (「겹침」 판정만).
- 삭제는 원본 ZIP·SHP 가 아니라 **UTF-8 작업 사본(GPKG)** 에서 한다 (`HeritageImport.cpp:45-125`, 주석 `:173` 「원본은 바꾸지 않는다」).
- 한 SHP 가 모두 범위 밖이면 그 SHP 는 올리지 않고, 종류 전체가 범위 밖이면 「%1%2: 조사구역 주변 5km 안에 든 자료가 없습니다.」 (`:285-295`). 500 m 로 자르는 코드는 **없다**.

### 3.3 올라가는 레이어 (이름·그룹·순서)
- 레이어 이름 = **SHP 파일 이름 그대로** (예: 「국가지정유산」), 이웃 시·군을 함께 받는 경우에만 뒤에 「 · <시군>」 (`HeritageImport.cpp:237-240`, `KaHeritageBrowserPlan.cpp:20-22`). 파일 이름이 없으면 종류 이름 (「지정유산」 등).
- 위치: 범례(레이어 창) **「참조 지도」 › 「<종류 이름>」 그룹** 안 (예: 참조 지도 › 지정유산 › 국가지정유산 …) (`:306-332`). 종류 그룹은 접힌 채, 레이어 노드도 접힌 채 올리며, 부모 그룹 체크가 꺼져 있으면 켠다 (`:325-331`). 같은 그룹 맨 뒤에 추가되고, 올린 뒤 `ensureSatelliteAtBottom` 으로 위성영상을 맨 아래로 둔다 (`:334`). 조사 데이터 그룹과 섞이지 않는다.
- 6종 이름: 「지정유산」 「현상변경허용기준」 「매장유산유존지역」 「문화유적분포지도」 「지표조사구역」 「발굴조사구역」 (`HeritageStyle.cpp:27-32`).
- 표지: 레이어 속성 `ka_hgis/heritage_dataset`(영문 키 6개 `designated_heritage` … `HeritageLayoutNumbers.cpp:81-88`), 다중 시·군이면 `ka_hgis/heritage_region` (`HeritagePledge.cpp:75-83`), 역할 「참조」 (`LayerOps.cpp:1052-1056`), `readOnly` 속성 true (`HeritageImport.cpp:278`; 이 속성이 실제 편집을 막는지는 이번에 확인하지 않음).
- 레이어 창 모양: 종류 색 견본 하나를 레이어 이름 줄에 붙인다 (`HeritageSiteLegend.cpp:44-74`).

### 3.4 색·선·글자 (`core/HeritageStyle.cpp`)
- 색은 **종류 하나에 한 색** (2026-09-13 사용자 확인 주석 `:144`): 지정유산 `#8E44AD`, 현상변경허용기준 `#E67E22`, 매장유산유존지역 `#2E86C1`, 문화유적분포지도 `#27AE60`, 지표조사구역 `#D4AA00`, 발굴조사구역 `#C2187D` (`:27-32`). 지정유산 안 6갈래도 모두 같은 색.
- 면: **채우지 않고 테두리만** (「채우면 위성·지적·수치지형도를 가린다」), 두께 0.35 mm (`:42-57, 134`). 선: 같은 색 0.35 mm (`:58-65`). 점: 지름 2.0 mm 원 (`:66-73`).

### 3.6 「엑셀 내보내기」와 「포함 수」 계산 (`core/NearbyHeritageCollect.cpp:166-258`)
- 대상: 지도에 올라온 유산 레이어 전부 (표지 → 그룹 이름 → 레이어 이름 → 「지정유산·등록문화유산·보호구역」 글자 순으로 종류 판정, `:65-79`). 없으면 「지도에 주변유적(유산) 레이어가 없습니다. 먼저 「유산」을 눌러 자료를 받아 오세요.」 (`:179`).
- 같은 **「유산코드」** 도형은 합쳐 한 곳으로 센다 (코드가 없으면 도형 번호로 구분, `:216-227`). 조사구역 도형과의 **최단거리**가 반경 이하(500 또는 1000 m, 인자 없으면 보이는 링 기준)인 곳만 남긴다 (`:233-235`).
- 거리 0(겹침)이면 방향·반경 구분 모두 「조사구역 내」. 아니면 반경 구분 「500m 이내」(500 m 이하) 또는 「1000m 이내」, 방향 8방위(「북, 북동, 동, 남동, 남, 남서, 서, 북서」, `:160-164`), 방위각(소수 1자리), 설명 「조사구역에서 %1쪽으로 약 %2m」 (`:236-249`). 거리 가까운 순으로 정렬 (`:253-256`).
- 엑셀 파일: 기본 파일명 「주변유적_현황_<반경>m.xlsx」, 조사 폴더에서 시작 (`MainWindowExport.cpp:512-540`), 시트 이름 「주변유적_현황」, 열 17개: 연번 · 자료구분 · 레이어명 · 유적명 · 유산코드 · 보고서명(서지) · 사업명 · 소재지 · 조사기관 · 시대 · 유적유무 · 허가번호 · 반경구분 · 방향 · 거리(m) · 방위각(도) · 위치설명 (`core/NearbyHeritageExport.cpp:13-60`). 완료 알림 「주변 %1m 이내 유적 %2곳(유적명·방향·거리)을 엑셀로 저장했습니다.」

## 4. 도면(조판)에서의 유산

### 4.1 도면 종류와 「주변유적」 전용 도면 여부
- 도면 종류는 4개뿐: 「조사구역도」(1:5,000), 「유적위치도」(1:25,000, 주변 지형에서 유적 위치를 넓게), 「유구배치도」(1:1,000), 「개별유구실측도」(1:100) (`core/LayoutService.cpp:85-157`, `koreanTitle :102-108`). **「주변유적 분포도」·「주변유적 현황」 도면 종류나 함수는 소스에 없다** (`분포도|주변유적 현황` 검색 결과는 엑셀 저장 창 제목과 한글 보고서 단계 이름뿐). 「유적위치도」의 기본 레이어 목록도 `survey_area` 하나뿐이고 유산 레이어는 따로 들어가지 않는다 (`:126-134`) — 유산은 아래의 일반 규칙으로 들어온다.
- 도면 만들기 단추 「도면」(Ctrl+L) 은 `MainWindowRibbon.cpp:552-557`, 본체는 `app/KaDrawingStudio.cpp` (도면 화면). 도면명 입력 예 「도면명 (예: 조사구역도, 유적위치도, 유구배치도)」 (`KaDrawingStudioSheets.cpp:48`).

### 4.2 지도 틀 안에서
- 도면 지도는 지도에서 **체크된 레이어**를 가져온다. 유산 종류 그룹 아래 체크된 레이어는 별도 규칙으로 꼭 넣는다 (`KaDrawingStudio.cpp:2121-2131`). 유산은 지도에서 「라벨 위로 다시 그리는」 덧지도 대상으로 분류돼 (`core/LayerTreeLabelStack.cpp:210-219`) 지적도 글자 위에 선이 보이게 한다 (`KaDrawingStudio.cpp:2165-2178` 주석).
- 번호는 도면 지도 위 또 하나의 투명 지도 항목 `ka_map_numbers` 에 **점 레이어 「도면번호」**(메모리)로 그린다 (`core/HeritageLayoutNumbers.cpp:1027-1110, 1112-1177`). 원 안에 굵은 번호(「Malgun Gothic」 Bold 1.82 mm)이고 원 색은 그 유적 종류 색, 글자색은 밝기에 따라 흑/백 (`inkFor :103-106`, 휘도 0.62 기준), 지름 `max(2.3, 1.0 + 자릿수×0.725) × 1.3` mm (`circleSize :108-110`). **지시선은 긋지 않는다** (「선을 긋지 말고 제위치에」 2026-10-19 현장 요청, `:1064`). 번호는 자기 유적 위(면 안)에 두고, 겹치면 가까운 빈 자리로 옮기며 범례 카드와 지도 틀 밖을 피한다 (`core/LayoutBadgePlacer`, `:972-1006`; 배치 알고리즘 본문은 이번에 읽지 않음).

### 4.3 번호 매기는 규칙 (`HeritageLayoutNumbers::update`, `:625-1025`)
1. **조사구역에서 500 m 이내만 번호** (`kNumberedNearSurveyM = 500`, `:194-217`; 조사구역 합집합을 500 m 넓힌 범위 ∩ 종이에 실제 나오는 지도 범위). 조사구역이 없으면 종이에 나온 모든 유적에 번호 (`:198-199` 주석). 500 m 밖 유적은 색 테두리로만 그려지고 번호·범례 줄이 없다.
2. 번호는 **종류(지정유산 등)마다 1, 2, 3…** (`counters[datasetName]`, `:723, 926`). 레이어 창에서 보이는 위쪽 레이어부터 (「프로젝트 트리 순서」, `:701, 725`).
3. 한 레이어 안에서 **같은 이름은 번호 하나** (단일 심볼이면 이름이 키, `:831-838`; 분류 렌더러면 분류 값이 키, `:822-830`). 순서는 이름(또는 분류 번호) 정렬 순 (`QMap`).
4. 이름은 「표시할 항목」에서 고른 열(`ka_hgis/label_field`), 없으면 3.4절 규칙 (`:769-770`); 이름이 비면 「무명」.
5. 축척 범위 밖(`isInScaleRange`) 레이어는 번호가 없다 (`:774`). 지도 틀 밖 유적은 번호가 없다 (종이 범위로 교차 검사).
6. 도면에서 번호 글자를 끄는 스위치: 레이어별 `ka_hgis/layout_numbers_visible` (`core/LayerLabelControls.cpp:98-102, 155-161`, 이름 「번호」).

### 4.4 범례
- 범례 제목 기본값 「범례」, 입력창 안내 「제목을 입력하세요」, 글자 5-24 pt 기본 10 pt 굵게 (`KaDrawingStudio.cpp:952-974`).
- 유산 레이어의 범례 줄은 **「(번호 원 기호) 유적명」** 한 줄씩: 원 기호는 색·번호가 들어간 원(`:1295-1309`), 글자는 유적명. 줄 순서는 번호 순서(레이어 안 `legendIndex`, `:1311`). 범례 줄은 **도면 지도에 실제로 번호가 찍힌 유적만** (`m_visibleKeys`, `:1237`), 번호가 하나도 없는 유산 레이어는 범례에서 뺀다 (`:1246-1252`). 종류 이름 줄(제목)은 숨긴다 (`setNodeLegendStyle Hidden` `:1315`).
- 유산이 아닌 벡터(지질·토양 등)는 범례를 지도 범위로 거르고, 유산은 위 번호표로만 거른다 (`:1195-1200, 1338-1361`). 범례에 유산 레이어를 빠짐없이 채우는 보충 `addMissingSheetLegendLayers` (`LayoutService.cpp:1425-1455`).
- 범례 제외 표지 `ka_hgis/omit_sheet_legend` 가 번호 점 레이어에 붙는다 (`HeritageLayoutNumbers.cpp:1041`).

### 4.5 이름 모드 (큰 축척)
- 도면 오른쪽 범례 카드의 체크 「1:5,000 이하에서 유적 이름으로 표시」 (말풍선 「켜면 1:5,000과 더 크게 본 축척에서 주변유적 번호 대신 유적 이름을 쓰고, 범례에는 유적 종류만 남깁니다」, `KaDrawingStudio.cpp:975-989`). 도면 속성 `ka_hgis/heritage_names_large_scale`.
- 켜져 있고 도면 축척이 1:5,000 이하(분모 5,000.5 미만, `kNamesMaxScale = 5000`, `HeritageLayoutNumbers.h:66`, `.cpp:630-632`)이면 번호 원 대신 **유적 이름 글자**(검정 2.2 mm 「Malgun Gothic」, 흰 테두리 0.5 mm, 상자 없음, `:112-123, 1066-1083`)를 같은 자리에 놓고, 범례는 **종류 이름 + 색 네모 한 줄**만 둔다 (`:1281-1293`).
- 축척이 5,000 보다 작으면(예 1:25,000) 이름 모드를 켜 둬도 번호 원을 쓴다.

### 4.6 거리·방향·표
- 도면에 방향·거리를 쓰는 기능, 「주변유적 목록 표」, 같은 번호를 연번으로 쓰는 표는 **도면 코드에 없다**. 유적 번호는 도면 안에서만 뜻이 있고, 엑셀의 「연번」(거리순 1..N, `core/NearbyHeritageExport.cpp:47`)과 서로 이어지지 않는다 (같은 번호 체계를 쓰는 코드가 없음).
- 표는 한글(HWP) 보고서에 있다: 「가까운 주변유적 20건 (<표 1-1>)」, 「부록 <표 1-2> 반경 %1m 주변유적 전체 목록」 (`core/HwpSurveyReportService.cpp:90, 136, 170`; 반경 값은 `NearbyHeritageExport::collect` 의 결과).
- 축척 바·좌표 격자 등 일반 도면 장식은 유산과 관계없이 도면 공통이다 (이번 조사 범위 밖).

### 4.7 내보내기에서 들어가는 것 / 일부러 빠지는 것
- PDF: 도면 화면의 「PDF 저장」, 인쇄, 제출 꾸러미가 같은 `HeritageLayoutNumbers::exportPdf` 를 쓴다 (`HeritageLayoutNumbers.h:55-57`, `KaDrawingStudio.cpp:3778-3797`, 저장된 도면 `core/LayoutService.cpp:1282-1292`). 번호는 PAL 라벨이 아니라 한 번에 계산한 핀이라 PDF 에서도 같다. 출력 중 도면이 바뀌면 「출력 중 도면이 변경되었습니다. 다시 내보내세요.」 (`:605-606`).
- 제출 꾸러미의 SHP 는 조사 도메인 레이어(저장소 규칙, `CLAUDE.md`)이고 유산 자료는 참조 지도다. 제출 설명서(README)는 유산 레이어를 「「%1」 · 국가유산 공간정보(인트라넷에서 받음) · 받은 날짜 %2 · 배포 제한 자료라 원본 파일은 넣지 않았습니다」 로 적는다 (`core/SubmitReadme.cpp:49-51`). 즉 **유산 원본 SHP 는 꾸러미에 넣지 않고, 도면 PDF 에 그려진 모양만 나간다** (꾸러미 조립 코드 `ExportService` 는 이번에 열지 않았으므로 「넣지 않는다」는 README 문구와 저장소 규칙에서의 결론).
- 점검표: 유산 레이어가 지도에 있으면 경고 항목 `HERITAGE_PLEDGE_SCOPE` (심각도 warn): 「국가유산 인트라넷 자료(주변유적)가 지도에 있습니다. 도면에 넣어 제출해도 되는지 서약서 이용 범위(조사폴더 주변유적/receipts/서약서-*.txt)를 확인하세요.」 (`data/rules/drawing_checklist.v1.json:57`, 상태 계산 `core/ProjectStateBuilder.cpp:56`, `HeritagePledge.cpp:85-108`). 점검표 오류는 제출을 막지 않는다 (저장소 규칙).
