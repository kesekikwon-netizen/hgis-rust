# 결과 기록

검수를 통과해 올린 일의 결과를 날짜순으로 적는다. 묶음을 올릴 때마다 지시자가 덧붙인다.
사용자 지시(2026-11-14): 「모든 소유권이 너에게 있고 결과를 항상 기억하라」.

- 계획과 순서: `docs/RUST_PLAN.md`
- 기능별 C++ 대조표: `docs/PARITY_STATUS.md`
- C++ 보다 낫게 바꾼 것: `docs/EVOLUTION.md`
- 「같다」는 C++ 실물이 낸 값이나 C++ 코드 줄에 묶인 시험이 있을 때만 쓴다.

## 통과 절차 (2026-11-14부터)

1. 개발 창이 자기 작업 폴더에서 만들고 보고한다.
2. 새 맥락의 검수 에이전트가 C++ 코드·시험과 줄 단위로 대조한다.
3. 지시자가 시험을 다시 돌리고 인용한 C++ 줄을 직접 연다.
4. 통합 가지에서 전체 검증(린트, 시험, GDAL 기능 시험, 릴리스 빌드, 실행 확인)을 OSGeo4W 없는 환경에서 돌린다.
5. GitHub 에 올리고, 자동 검사(GitHub Actions)가 통과하면 실제 프로젝트 폴더와 바탕화면 바로가기가 여는 앱을 그 커밋으로 맞춘다.

### 운영에서 배운 것

- 이 PC 의 전체 검증과 GitHub 자동 검사가 서로 다른 컴파일러를 쓰고 있었다(1.91 과 1.100). 위성지도 수정이 그 때문에 한 번 막혀 30분 늦어졌다. 컴파일러 버전을 저장소에 고정한다.
- 스킬 팩(superpowers)은 Gemini 쪽도 공식 지원한다. 지시자가 확인 없이 「Claude 전용」이라고 답했다가 사용자 지적으로 바로잡았다. 도구가 무엇을 못 한다고 말하기 전에 지금 문서를 확인한다.
- 올린 것만으로는 사용자가 여는 앱이 바뀌지 않는다. 적용까지가 한 단계다.
- 지시마다 새 작업 폴더를 만들면 큰 라이브러리를 처음부터 다시 빌드해 PC 가 느려진다. 창마다 폴더 하나를 계속 쓴다.
- 개발 중 지도 화면 사진이 실제 키로 타일을 받고 있었다(오전 11시대 249장). 지도 사진을 멈추고 접속 차단 스위치(NET0c)를 만들고 있다.
- 대조표에 적힌 C++ 위치는 주장일 뿐이다. 개발자가 먼저 확인하고 검수가 다시 확인한다.
- 지시자의 지시 초안도 틀릴 수 있다. 보내기 전에 C++ 코드를 직접 다시 읽는다.
- 사용자가 앱을 쓰다 겪은 불편은 계획 순서보다 먼저 고친다.
- 컴파일러 차이로 자동 검사가 한 번 더 막혔다(MAP1b). 원인을 안 첫 번째 때 바로 고정했어야 했다. 이제 이 PC 와 GitHub 가 같은 1.91.1 을 쓴다(TC1).
- 스킬을 썼다는 보고만으로는 알 수 없다. 개발 창들이 남긴 작업 기록을 세었다: 스킬 설치(14시 21분) 뒤 보낸 지시 13건 중 11건이 그 지시 안에서 스킬 문서를 열었고 2건은 앞서 읽은 것으로 진행했다. 코드를 고친 8건 중 시험을 먼저 쓴 것이 분명한 것은 4건이다. 보고서 두 건은 「시험 먼저」라고 적었지만 기록은 코드를 먼저 수십~160줄 고쳤다. 그래서 새 시험이 실패한 줄을 보고서에 적게 했고, 합치는 기준은 계속 독립 검수다.
- 문서 찾기 도구(context7)는 넣지 않는다. 고정한 버전의 라이브러리 원본이 이 PC 에 있고 창들이 이미 읽는다(이날 약 100회, C++ 원본은 약 1,000회). 바깥 색인은 우리 버전과 다를 수 있다.
- 작업 폴더를 준비한 뒤에는 가지와 커밋을 다시 읽어 확인하고 나서 지시를 보낸다. 효과음 지시가 예전 기준 폴더로 나갈 뻔했다.
- 좌표 변환을 직접 계산해 보았다. 앱 일부(배경지도 타일 위치, 장소 검색, 받을 범위 계산)가 손으로 짠 근사식을 쓰고 있었고, 정확한 식과 전국 격자로 비교하니 기본 좌표계에서 경주·부산은 남북으로 4 ~ 15 mm, 서울·광주는 동서로 27 ~ 36 mm, 제주는 71 mm, 전국 범위의 가장자리에서는 최대 2.6 m 어긋난다. 조사 자료의 그리기·저장·자석·검수는 지금 코드에서 PROJ 를 쓴다. 기존 시험은 한 곳의 다섯 점을 허용 오차 5 cm 로만 보고 있었다. PROJ 하나로 통일한다(GEO1).
- 따로 검수를 통과한 두 작업을 합치면 깨질 수 있다. 성능 측정 도구와 접속 차단 스위치가 그랬다: 배포용 빌드에서만 드러났고 전체 검증이 올리기 전에 잡았다. 합친 뒤의 부분 점검에도 배포용 빌드를 넣는다.
- 보안 규칙은 보고된 글자를 막는 식이 아니라 안전한 형태만 허용하는 식으로 쓴다. 접속 차단 스위치의 파일 주소 규칙을 지시자가 처음에 전자로 고쳤다가 검수에 다시 뚫렸다.
- 「받기」의 중간 창: 사용자가 물었고, 답은 「아직 전부는 아니다」였다. 지적도·DEM 은 진행 창이 뜬다. 지시 DL2(창이 닫히고 아래 게이지만), WIN1(검은 창이 어떻게 실행해도 뜨지 않게), WB1·WB2(숨은 브라우저)로 맞춘다.
- 개발 창 여덟 개로 하루가 끝나기 전에 AI 크레딧이 바닥났다. 창을 늘리면 더 빨리 닳는다. 창마다의 상태는 작업 폴더와 재시작표에 남아 있어 재접속 뒤 이어서 한다.
- GitHub 자동 검사를 기다리던 스크립트가 통신 오류로 기다림이 끊긴 것을 「검사 실패」로 읽었다(18시). 검사 자신이 끝났다고 할 때까지 되풀이해 묻도록 고쳤다. 효과음 묶음은 18시 14분에 적용됐다.
- 검수 도우미에게 「임시 파일은 끝에 지워라」고만 적었더니 지시자의 임시 작업 폴더를 통째로 지웠다(18시 26분). 지시서 대기열은 따로 둔 사본이 온전했고 도구는 세션 기록에서 되살렸다. 지시자의 자료는 장부 옆 폴더에만 두고, 도우미에게는 「자기 하위 폴더를 만들어 그것만 지워라」고 적는다.
- 모델과 노력 강도는 지시의 난이도에 맞춰 지시자가 창마다 정하고 기록한다(사용자 지시, 18시 46분 ~ 50분). 어려운 일(보안, 좌표·수학, 동시 처리, 화면 도구 올리기)은 Gemini 4 Carbon high 로 하되 동시에 세 창까지, 보통 개발은 Gemini 4 Hydrogen high, 한 번 되돌려진 일의 수정은 한 단계 위, 조사·문서는 Hydrogen medium. 창의 모델은 고르기 화면을 키 입력으로 조작해 바꾸고 에이전트의 기록에서 바뀐 것을 확인한다. 명령을 글로 보내면 지시로 들어가 한 턴을 쓴다(지시자가 한 번 그렇게 잘못 보냈다).
- 글자를 C++ 앱만큼 또렷하게 하려면 화면 도구(egui)를 올려야 하고, 그 전에 고정한 컴파일러부터 올려야 한다: egui 0.34 · 0.35 는 컴파일러 1.92, 0.36 · 0.37 은 1.95 가 필요한데 저장소는 1.91.1 로 고정돼 있다. 순서는 컴파일러 올리기(TC2) → 화면 도구 시험(EG0)이다.
- 리본 단추 26개를 C++ 과 하나씩 대조했다(코드 읽기): 묶음·이름·아이콘·단축키는 모두 같다. 설명글은 15개가 다르다(10개는 C++ 이 앞에 붙이는 「이름 — 」가 없고, 5개는 글 자체가 다르거나 없다). 조사를 열기 전에는 꺼져 있어야 할 단추 다섯 개가 눌리고, GeoTIFF 단추는 동작하지 않는다. 같은 방식으로 C++ 의 창들을 다섯 묶음으로 나눠 단추·문구를 하나씩 대조하는 조사(UI2-a ~ e)를 맡긴다.
- 개발 창 16개를 켜 두기만 해도 메모리 31 GB 가운데 5 ~ 7 GB 만 남는다. 빌드하는 창은 동시에 여섯 개까지만 돌리고, 나머지에는 빌드가 없는 조사 일을 준다.
- 장부의 시각은 시계를 읽어 적는다. 어림해 적은 시각이 한 시간 가까이 틀려 재시작표의 「최신」 절이 뒤바뀔 뻔했다.
- 한 묶음에서 지시 네 건(FONT1b, DL2, MAP1e, P-L1b)이 「범위에 없는 파일이 필요하다」며 멈췄고, 네 번 모두 개발 창이 옳았다. 지시를 보내기 전에 목표를 실제로 바뀌어야 하는 줄까지 따라가 그 파일을 범위에 넣는다. 다섯 번째(WIN1b)는 이미 합친 작업의 예전 가지에 후속 지시를 낸 탓이었다: 후속 지시는 통합 가지 위에서 시작한다.
- 전체 검증이 도는 동안 통합 가지에 커밋을 더하면 검증 기록이 남지 않는다(19시 59분, 문서 커밋 하나 때문에 검증을 다시 돌렸다). 검증 중에는 통합 가지를 건드리지 않는다.
- 남은 메모리만 보고 빌드하는 창을 늘리면 안 된다. 19시 20분 ~ 45분에 메모리 여유를 근거로 여섯 개에서 열한 개로 늘렸고, CPU 가 100% 인 채로 30분 뒤 PC 가 꺼졌다. 이제 빌드는 동시에 여섯 건까지, 빌드 하나는 CPU 3개와 시험 스레드 4개까지로 묶고(작업 폴더들에만 적용되는 설정 파일), 새 빌드를 붙이기 전에 CPU 와 메모리를 잰다. 다시 켠 뒤 여섯 건이 빌드할 때 CPU 는 평균 42%, 최대 60% 였다.
- PC 가 갑자기 꺼지면 마지막 1 ~ 2분에 쓰던 파일이 빈 바이트로 채워진다. git 색인도 예외가 아니어서, 깨진 줄 모르고 쓰면 「바뀐 것 없음」으로 보인다. 지시를 다시 보내기 전에 깨진 파일부터 찾는다. 개발 창의 작업 기록에는 파일에 쓴 내용이 통째로 남아 있어, 커밋하지 않은 소스 4개를 거기서 되살렸다.
- 지시자의 장부와 도구는 git 이 추적하지 않는 파일이라 묶음을 보낼 때마다 따로 보관해야 한다. 꺼졌을 때 마지막 보관은 7시간 전이었고, 잃은 것이 장부 몇 줄에 그친 것은 운이었다.
