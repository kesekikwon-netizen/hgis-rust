## 2. QGIS 엔진이 잘하는 것 / 못하는 것

### 잘하는 것
- 레이어 = 데이터 + 심볼 + 표시 + 순서를 한 객체로. 추가·삭제·재정렬이 자유롭다.
- 좌표 변환을 표준(EPSG) 기반으로. 온더플라이(OTF) 투영.
- 1,274회짜리 지오메트리 연산(교차·차집합·버퍼)을 정확하게.

### 못하는 것 (Rust 가 이기게 될 지점)
- **무겁다**: QGIS 코어만 수십 MB. 앱 전체가 7.6MB exe + OSGeo4W 수백 MB.
- **설치가 어렵다**: OSGeo4W 환경변수 없으면 `0xC0000135` 로 죽는다(오늘 확인).
- **헤드리스 검증이 느리다**: GUI 창을 띄워야만 눈으로 확인된다.
- **테스트가 어렵다**: QPainter 렌더 결과를 픽셀로 검증하기 번거롭다.
- **재현 불가**: QGIS 버전이 바뀌면 렌더 결과가 미묘하게 달라진다.

## 3. 더 나은 엔진 — 5가지 원칙

### 원칙 1: 그리기를 **데이터**로 (지금 만든 것)
레이어가 z순서·표시·스타일을 들고 있으면, 화면 코드는 순서대로 칠하기만 한다.
→ 레이어 추가 = 데이터 추가. 코드 수정 없음.

### 원칙 2: 엔진은 **렌더러를 모른다** (지금 만든 것)
`DrawShape`(중립 도형)만 낸다. egui·PDF·SHP 어디에도 같은 결과.
→ QGIS 는 QPainter 에 묶여 있다. Rust 는 안 묶인다. **이게 QGIS 보다 나은 점.**

### 원칙 3: **모든 것이 검증 가능**해야 한다
엔진이 도형 목록을 내므로, 화면 없이 시험할 수 있다:
```rust
let shapes = render_stage(&stage, &xf, opts);
assert_eq!(count_shapes(&shapes), 42);   // 창 띄우지 않고 검증
```
→ QGIS 는 이게 안 된다. **Rust 만 가능한 검증.**

### 원칙 4: **좌표계를 값으로** 들고 다닌다
C++ 은 `QgsCoordinateReferenceSystem` 객체를 503회 넘긴다.
Rust 는 `WorkCrs` 열거형으로 이미 한다. 더 단순하고 틀릴 수 없다.

### 원칙 5: **한 방향 의존** — 엔진 → 앱 금지
```
strata-types ← strata-geo ← strata-canvas2d(layer_engine) ← strata-app
```
엔진은 앱을 모른다. 그래야 테스트·재사용이 된다.

## 6. QGIS 를 쓰지 않기로 한 근거

원래 C++ 규칙은 "PROJ/GDAL/렌더링을 재구현하지 않는다"였다. **그 규칙은 C++ 앱에만
해당한다.** Rust 앱은 애초에 QGIS 를 링크할 수 없다(라이선스·배포·플랫폼).
따라서 Rust 는 같은 **결과**를 내는 것이 목표이고, 그 결과를 검증하는 방법은
QGIS 보다 낫다(원칙 3). 이 차이를 문서로 남긴다.
