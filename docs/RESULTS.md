# 결과 기록

검수를 통과해 올린 일의 결과를 날짜순으로 적는다. 묶음을 올릴 때마다 지시자가 덧붙인다.

- 계획과 순서: `docs/RUST_PLAN.md`
- 기능별 C++ 대조표: `docs/PARITY_STATUS.md`
- C++ 보다 낫게 바꾼 것: `docs/EVOLUTION.md`
- 「같다」는 C++ 실물이 낸 값이나 C++ 코드 줄에 묶인 시험이 있을 때만 쓴다.

## 통과 절차 (2026-11-14부터)

1. 개발 창이 자기 작업 폴더에서 만들고 보고한다.
2. 새 맥락의 검수 에이전트가 C++ 코드·시험과 줄 단위로 대조한다.
3. 지시자가 시험을 다시 돌리고 인용한 C++ 줄을 직접 연다.
4. 통합 가지에서 전체 검증(린트, 시험, GDAL 기능 시험, 릴리스 빌드, 실행 확인)을 OSGeo4W 없는 환경에서 돌린다.
5. GitHub 에 올리고, 자동 검사(GitHub Actions)가 통과하면 실제 프로젝트 폴더와 바탕화면 바로가기가 여는 앱을 그 커밋으로 맞춘다.

### 운영에서 배운 것

- 올린 것만으로는 사용자가 여는 앱이 바뀌지 않는다. 적용까지가 한 단계다.
- 지시마다 새 작업 폴더를 만들면 큰 라이브러리를 처음부터 다시 빌드해 PC 가 느려진다. 창마다 폴더 하나를 계속 쓴다.
- 개발 중 지도 화면 사진이 실제 키로 타일을 받고 있었다(오전 11시대 249장). 지도 사진을 멈추고 접속 차단 스위치(NET0c)를 만들고 있다.
- 대조표에 적힌 C++ 위치는 주장일 뿐이다. 개발자가 먼저 확인하고 검수가 다시 확인한다.
- 지시자의 지시 초안도 틀릴 수 있다. 보내기 전에 C++ 코드를 직접 다시 읽는다.
- 사용자가 앱을 쓰다 겪은 불편은 계획 순서보다 먼저 고친다.
