## 1. 목표

1. **현장 한 바퀴**: 새 조사 → 조사구역·유구·유물·단면·기준점 기록 → 검수 → 제출 꾸러미(EPSG:5179 SHP + MANIFEST) + 조사도면 PDF 까지 Rust 판에서 할 수 있고, 결과물이 C++ 판과 같다.
2. 그다음 **세부 일치**: C++ 창 65개, 우클릭 메뉴, 리본, 글자·여백까지 같다.
3. **판정 기준**: C++ 앱이 실제로 만든 파일·화면과 맞대 본다. 시험 통과나 「단추가 있음」은 완성이 아니다.
4. **기능 기준**: 지금의 C++ Strata 다. C++ 에 있는 기능은 Rust 판에서 모두 쓸 수 있어야 한다. 엔진을 바꿔도 기능·문구·검수 규칙·도면 양식·조사 레이어 규칙은 Strata 것이다.
5. **겉모양**(사용자 2026-11-14): 지금의 디자인을 이어 간다. 그 큰 틀 안에서 더 고급스럽게 바뀌는 것은 허용한다. 그래서 2번의 「글자·여백까지 같다」는 기능·문구·순서에 적용하고, 색·여백·모서리 같은 겉모양은 지시에서 따로 정한 만큼 달라질 수 있다.
   `docs/DESIGN_SPEC_FINAL.md` 의 「제안」 항목은 그런 지시를 쓸 때 재료로 쓴다.
6. **자료 받기 화면**(사용자 2026-11-14): 자료를 받는 사이트마다 뜨던 다운로드 창·자료 받는 창은 없애거나 숨겨도 된다. 앱 창 아래에 작은 게이지로 진행을 보이고, 실패하면 왜 실패했는지 알 수 있는 오류 코드만 보인다. 사용자가 골라야 하는 것(범위, 도엽, 계정)이 있는 단계는 남긴다(2.8절).
7. **사이트 접속**(사용자 2026-11-14): API 키가 사이트의 한도와 부딪히지 않게 하고, 아이디로 로그인하는 사이트에서 계정이 막히지 않게 하고, 로그인이 필요 없는 사이트에도 공격처럼 보이지 않게 한다(2.8절).
8. **진화**(사용자 2026-11-14): C++ 기능을 모두 옮긴 뒤에 멈추지 않는다. C++ 보다 나아질 방법이 있으면 나아간다. 다만 기능을 옮기는 일이 먼저이고, 달라지는 점은 지시에 「사용자 결정」으로 적는다. 사용자는 같은 날 「이 앱은 항상 진화해야 한다」고 다시 못박았다. 그래서 이 계획에는 끝이 없다: 나아질 후보를 `docs/EVOLUTION.md` 에 모으고, 옮기는 일과 나란히 계속 지시로 만든다(7절).
9. **저작권**: 언젠가 남의 저작권에 묶이지 않는 독자적인 앱이 된다(2.7절). 웹·GitHub·georust 코드에도 묶이지 않는 것이 바람이지만, 일이 매우 커서 지금은 있는 부품으로 시작하고 부품마다 라이선스와 출처를 적어 둔다.

## 2. 엔진 설계 — 무엇을 어디서 가져오나

### 2.1 원칙 (C++ 앱이 실제로 쓰는 엔진을 따라간다)

C++ Strata 소스를 확인한 결과, C++ 은 두 엔진 위에 서 있다.
- **GDAL 을 직접 부르는 일**(23개 파일): 제출 SHP, 등고선, DXF, GeoTIFF, DEM, 주변유적 엑셀, 조사 파일 구조 등.
- **QGIS 에 맡기는 일**: 지도 그리기, 도면 배치·PDF, 라벨, 배경지도 타일, 래스터 표시.

그래서 Rust 판은 이렇게 맞춘다.

| C++ 이 쓰는 것 | Rust 판이 쓰는 것 | 이유 |
|---|---|---|
| GDAL 3.14 (직접 호출) | **같은 GDAL 3.14** (georust `gdal` 크레이트) | 같은 엔진이면 파일이 바이트까지 같아진다 |
| QGIS (그리기·배치·타일) | **RustGIS 최신판 v0.6.0** (render·map·tiles) | Rust 로 된 QGIS 자리. 2026-11-09 판이 지금 최신이다 |
| PROJ·GEOS (QGIS·GDAL 안) | PROJ·GEOS (이미 연결, E0) | 좌표·도형 계산을 C++ 과 같은 엔진으로 |
| Qt 화면 | egui 화면 (지금 0.31) | 화면은 Strata 가 직접 그린다 |

- 이 엔진들은 **연결부 크레이트 `strata-engine` 하나**에서만 부른다. 화면·저장 크레이트는 엔진 형식을 모른다.
- 엔진의 기본값이 Strata 규칙을 바꾸지 못한다. 문구·검수·도면 양식·조사 레이어는 C++ Strata 그대로다.

### 2.2 구조

```
화면  strata-app (egui) ── 리본 · 지도 · 레이어 패널 · 창 · 오른쪽 카드   ← 디자인·기능 = C++ Strata
  │
  ├─ 조사 파일  strata-storage ── 조사 GPKG(C++ 형식, 검수 통과) ⇄ 편집 버퍼 ⇄ 안전 저장
  │
  ├─ 엔진      strata-engine ─┬─ PROJ · GEOS ......... 좌표 변환, 도형 고치기 (연결됨)
  │                           ├─ GDAL 3.14 .......... SHP · 등고선 · DXF · GeoTIFF · DEM · 엑셀 (R2-spike 부터)
  │                           └─ RustGIS v0.6.0 ...... 지도·도면 그리기, PDF/SVG, 라벨, 타일 (관문 S2 뒤)
  │
  ├─ 검수·제출  strata-check-export ── 검수 27가지 → 제출 꾸러미(GDAL 로 SHP)
  ├─ 자료 받기  strata-net ──────── VWorld 지도·지적도, 국가유산 인트라넷, 수치지형도
  └─ 계정      strata-secrets ──── C++ 과 같은 저장소(ini · Windows 암호화)
```

### 2.4 지켜야 할 조건

- **부품 2주 규칙**(공급망 안전, 지시자 결정): 나온 지 2주가 안 된 부품 판은 넣지 않는다.
  - RustGIS v0.6.0 은 11/23 부터 넣을 수 있다.
  - SQLite 판 충돌을 푸는 proj 0.32·proj-sys 0.28 은 11/26 부터다.
  - 그래서 **RustGIS 를 실제로 붙이는 날은 11/26(관문 S2)** 이다. 그 전에 시험 연결과 준비를 끝낸다.
- **라이선스**:
  - RustGIS 는 Apache-2.0 이다. 넣으면 배포하는 프로그램 전체를 **GPL-3.0-or-later** 로 내야 한다. 우리 코드는 GPL-2.0-or-later 라서 가능하다.
  - 정보 창의 고지를 이에 맞게 바꾼다. 사용자 확인을 R1b 합치기 전에 받는다.
  - GDAL 은 MIT 계열이다. 같이 배포하는 DLL 마다 고지 파일을 둔다.
- **배포·빌드**:
  - GDAL 은 DLL 묶음으로 같이 내거나, 필요한 드라이버만 넣어 정적으로 빌드한다(spike 에서 결정).
  - CI(GitHub)에도 GDAL 을 설치하는 단계를 넣는다.

### 2.5 R2-spike 결과 (2026-11-13, 지시자가 저장소 밖에서 직접 시험)

- **결과**: demo 조사 사본의 7개 조사 레이어를 Rust 로 EPSG:5179 SHP 로 썼다. **35개 파일 모두 C++ 제출 꾸러미와 바이트까지 같다.**
  - 기준: `docs/senior/ref-files/cpp-submit-package-demo/`
  - 같은 결과가 GDAL Python 과 Rust 양쪽에서 나왔다.
- **부품**: georust `gdal` 0.19.0 + `gdal-sys` 0.12.0(2025-12-23, MIT)을 OSGeo4W GDAL 3.14 에 연결했다.
  - 빌드 때 `GDAL_VERSION=3.12.0` 으로 미리 만든 연결 코드를 쓴다.
  - 3.14 머리말로 새로 만들면(bindgen) 0.19 이 컴파일되지 않는다(GDT_Byte 이름 바뀜). 그래서 쓰지 않는다.
- **C++(QGIS) 쓰기 규칙**(꾸러미 바이트로 확인):
  - 첫 칸은 `fid` N(20,0)이다.
  - 글은 C(254), 실수는 N(24,15)로 쓴다.
  - 이름은 `survey_name`→`surv_name`, `artifact_no`→`artif_no` 로 줄인다.
  - `ENCODING=UTF-8` 이다.
  - `.dbf` 머리말 2~4 바이트는 쓴 날짜다(같은 날이 아니면 이 3 바이트만 다르다).
- **실행에 필요한 것**:
  - GDAL DLL 51개, 137 MB(OSGeo4W `gdal-dev314.dll` 과 그 의존 DLL)
  - GDAL·PROJ 자료 폴더
  - E0 확인: 우리 내장 PROJ 9.6.2 도 OSGeo4W 9.8.1 의 proj.db 로 좌표 문을 통과한다.
- **판정**: R2 는 `gdal` 크레이트로 한다. `shapefile` 크레이트 대안은 쓰지 않는다.
  - CI(windows-latest)에는 OSGeo4W gdal-dev 를 해시 고정으로 설치하는 단계를 넣는다.
  - 등고선(W-29)·DXF(R6)·엑셀(W-H1)·GeoTIFF 쓰기(R7)도 같은 연결부로 이어 간다.
- **아직 확인 안 한 것**: EUC-KR·5186 꾸러미(bad.gpkg)는 R2 검수 때 C++ 하네스 결과와 맞대 본다. 실행 DLL 은 OSGeo4W 개발판(3.14.0dev)이라 판을 고정해 함께 배포하고, OSGeo4W 가 없는 깨끗한 PC 에서 도는지는 첫 판 배포 전에 시험한다.

### 2.6 C++ 과 얼마나 같아지나 (2026-11-13 점검)

| 묶음 | 기능 | 같아지는 정도 | 근거·남은 시험 |
|---|---|---|---|
| 같은 엔진 → 같은 파일 | 제출 SHP, 등고선·DXF·엑셀·GeoTIFF 쓰기 | 파일이 바이트까지 같아야 통과 | SHP 35/35 같음(demo, UTF-8·5187). 나머지는 GDAL 연결 뒤 같은 문 |
| 우리 저장 코드 → 같은 구조 | 조사 파일 열기·저장 | 7개 표 구조·판 도장이 C++ 과 같아야 통과(파일 전체가 바이트로 같지는 않다) | C++ 조사(demo)를 Rust 판에서 고쳐 저장한 사본을 C++ 실물이 오류 없이 엶(2C). Rust 판에서 새로 만든 조사는 작업공간이 없어, C++ 에서 제대로 열리는지 아직 시험하지 않았다(2D) |

### 2.8 자료 받기 화면과 사이트 접속 (2026-11-14 사용자 지시)

C++ 과 일부러 다르게 가는 두 가지다. 먼저 사실을 조사하고(DL0·NET1), 그 결과로 설계해서 지시한다(4.2절).

**아래 게이지**

- 자리: 앱 창 맨 아래(상태 줄). 작게 한 줄이다. 받는 일이 없으면 보이지 않는다.
- 보이는 것: 무엇을 받는지(예: 「지적도」), 진행 정도, 취소. 여러 개를 함께 받으면 한 게이지에 모아 보이고 개수를 적는다.
- 다시 받는 중: 스스로 되살리는 동안에는 게이지에 「다시 받는 중(n번째)」과 까닭 한 줄을 보인다. 실패가 아니다.
- 실패: 사용자가 손봐야 하는 일로 멈췄을 때만, 오류 코드와 한 줄 이유를 보인다. 코드는 멈춘 까닭마다 하나로 고정한다(계정 없음, 로그인 거절, 키 없음·키 거절, 폴더 없음, 사이트 화면이 바뀜 등). 목록은 DL0 조사 뒤 정한다.
- 남기는 창: 사용자가 골라야 하는 단계(받을 범위, 도엽 고르기, 계정 넣기). 진행·결과만 보이던 창은 게이지로 옮긴다.
- 받은 파일의 자리·이름·지도에 추가되는 방식은 C++ 과 같게 둔다.

**숨은 브라우저**(사용자 2026-11-14: 「없으면 만들어라」, 「창을 만들되 프로그램에는 보이지 않게」, 「C++ 안에 어떻게 만든지 다 나와 있다」, 「더 나은 방법이 있다면 소유권은 너에게 있다」)

- 아이디로 로그인하는 사이트(국가유산 인트라넷, 국토지리정보원)는 C++ 처럼 진짜 브라우저 엔진으로 접속한다. Rust 판에는 Windows 에 들어 있는 WebView2 를 붙인다(`strata-webview`, 지시 WB0).
- 그 창은 화면에 보이지 않는다. 사용자가 보는 것은 아래 게이지와, 실패했을 때의 이유뿐이다.
- 흐름(로그인, 양식 채우기, 내려받기)은 C++ 소스(`KaHeritageBrowser.cpp`, `HeritageIntranetFlow.cpp`, `KaTopographicBrowser.cpp`, `data/providers/ngii-topographic.js`)를 그대로 옮긴다(WB1·WB2). 더 나은 길이 있으면 지시자가 정한다.
- **한 번 시작한 받기는 실패로 끝나지 않는다**(사용자 2026-11-14: 「한번 받을 때 실패는 없게 하라」. C++ 소스에도 같은 결정이 적혀 있다: `KaHeritageBrowser.cpp:140` 「재시도는 끝없이 계속한다(사용자 결정)」).
  - 사이트가 파일 대신 웹페이지를 주거나, 전송이 끊기거나, 빈 파일·크기가 다른 파일이 오거나, 세션이 풀리면 C++ 처럼 스스로 되살린다: 5초·10초·20초, 그 뒤로는 30초씩 기다렸다가 공식 화면을 다시 열어 같은 자료를 다시 받는다(`KaHeritageBrowser.cpp:504-564`). 정상 파일이 디스크에 놓일 때까지 계속하고, 사용자는 언제든 취소할 수 있다.
  - 서버가 파일을 만드는 40~120초는 실패가 아니라 기다림이다(`:858-866`). 그동안 다시 요청하지 않는다.
  - 받은 파일은 크기와 내용을 확인한 뒤에만 「받음」으로 친다(`:1184-1198`, `:1382-1390`).
  - 실패로 끝나는 것은 사용자가 손봐야 하는 일뿐이다: 계정이 없음, 사이트가 로그인을 거절함(다시 넣지 않는다, `:927-931`), 저장할 폴더가 없음·쓸 수 없음, 사이트 화면이 바뀌어 단계가 더 나아가지 못함(`:871-875`). 그때는 게이지 자리에 이유를 보인다.
  - 시작하기 전에 사이트에 닿지 않고도 알 수 있는 것(계정, 폴더, 디스크, 인터넷, 이미 받은 자료)을 먼저 확인해 헛걸음을 없앤다.
  - 같은 원칙을 모든 받기(DEM, 지적도, 지도 타일, 주소 찾기)에 쓴다. 일시적인 실패는 간격을 두고 계속 다시 시도하고, 키 거절처럼 사용자가 손봐야 하는 것만 이유와 함께 멈춘다. 다시 시도는 몰아치지 않는다(간격은 받기마다 정해 둔다).
- curl 로 브라우저인 척하던 지금의 길은 없앤다(NET0b).
**사이트 접속 규칙**(NET1 조사 뒤 숫자를 정한다)

- 사이트마다 동시에 보내는 요청 수와 요청 사이 간격에 상한을 둔다. 한 곳(연결부)에서만 요청을 보낸다.
- 사이트가 한도 초과나 일시 장애를 알리면(HTTP 429·503 등) 기다렸다가 다시 하고, 횟수에 끝을 둔다. 4xx 는 되풀이하지 않는다.
- 이미 받은 자료는 다시 받지 않는다(디스크 보관).
- 로그인 사이트는 한 번에 한 세션만 쓰고, 로그인이 거절되면 스스로 다시 시도하지 않고 사용자에게 알린다.
- 키·비밀번호·세션 값은 로그·오류 글·파일 이름·화면에 나오지 않는다.
- 요청이 자기를 무엇이라고 밝히는지(User-Agent·Referer 등)는 사이트의 공개 이용 조건에 맞춘다. C++ 이 브라우저처럼 밝히던 곳은 NET1 결과를 보고 사이트별로 정한다.
- 시험과 도구는 실제 사이트에 접속하지 않고, 사용자의 키·계정을 쓰지 않는다.

## 3. 순서 — 관문 S2 를 기준으로

spike 가 성공했으므로 위험이 가장 작아진 **R2 를 F1c 바로 다음**으로 당긴다. 결과물(제출 꾸러미)이 가장 크다.

```
지금 ──────────────────────────────────── 11/26 관문 ─────────────────────────────────────▶
F1c(진행) → R2 제출 꾸러미(GDAL) → M2 선·점·꼭짓점 → 2D 작업공간 → E1    R3-spike(11/23~) → S2 → R1b    R3 도면 PDF → R4 타일 → R5 라벨 → R7 GeoTIFF → R9 음영 → M5 자료 받기 → 4.1 끈 기능 잇기 → M6 창 세부
          (F1d~g 를 사이사이에)                                       (RustGIS 시험·연결)            (여기부터 RustGIS 위에 짓는다)
```

- **관문 전**: RustGIS 가 필요 없는 일을 한다 — 기록 도구, 제출(GDAL), 손으로 짠 좌표 계산 정리, 남은 가짜 걷어 내기.
- **관문**: 부품 판을 올리고(S2) RustGIS 를 연결부에 붙인다(R1b). 저장·열기·좌표 시험을 모두 다시 맞대 본다.
- **관문 뒤**: 도면 PDF·타일·라벨·GeoTIFF 는 처음부터 RustGIS 위에 짓는다. PDF 를 두 번 만들지 않기 위해서다.

## 6. 일하는 방식

- 지시자(Claude 세션 하나): 계획, 지시, 검수, 합치기. 소스는 고치지 않는다.
- 개발자(안티그라비티 창 여덟): 창마다 작업 폴더(`.claude/worktrees/ag-*`)와 가지 하나를 쓴다. 지시는 그 폴더의 `ORDER.yaml`, 보고는 `REPORT.yaml` 이다. 구현, 시험, 자기 가지에 커밋까지 하고, 합치기와 올리기는 하지 않는다. 규칙은 `AGENTS.md` 다.
- 서로 겹치지 않는 파일을 고치는 지시만 함께 돌린다. 겹치면 지시자가 합칠 때 순서를 정한다.
- 지시 하나 = 작은 기능 하나다.
  - C++ 근거(파일:줄)와 기대값을 주고, 시험을 먼저 쓰게 한다.
  - 검수는 C++ 실물과 맞대 본 뒤 통과시킨다.
- 개발자 규칙 전문은 `AGENTS.md`, 지시자의 장부와 지시 초안은 `docs/senior/`(작업 사본에만 있음)에 있다.

## 7. 진화 고리 (2026-11-14 사용자 지시 「이 앱은 항상 진화해야 한다」)

옮기는 일이 끝나는 날이 이 앱의 끝이 아니다. 아래 고리를 계속 돌린다.

1. **모은다**: 개발자는 지시를 하다가 C++ 보다 나아질 길을 보면 고치지 않고 보고서의 `evolve` 칸에 한 줄 적는다. 지시자는 검수와 조사 문서에서 본 것을 더한다. 모두 `docs/EVOLUTION.md` 로 간다.
2. **고른다**: 지시자가 근거·효과·위험을 보고 순서를 정한다. 화면이 눈에 띄게 달라지거나 사이트 이용 방식·라이선스가 걸린 것은 사용자에게 한 번 묻는다.
3. **지시한다**: 보통 지시와 같은 형식이다. 어떤 기능이든 먼저 C++ 과 같게 실제로 돌고, 그다음에 바꾼다. 사용자가 일부러 다르게 정한 것만 예외다.
4. **돌려 둔다**: 옮기는 지시가 밀려 있어도 창 하나쯤은 진화 지시나 그 조사에 쓴다. 옮길 것이 끝나면 모든 창이 진화 목록으로 일한다.
5. **닫지 않는다**: 어떤 문서에도 「완성」이라고 쓰지 않는다. 판을 낼 때마다 진화 목록에서 무엇이 들어갔는지 적는다.
