# 메뉴와 상호작용의 현재 추적 기준

사용자의 2026-11-18 추가 지시에 따라 현재 C++ 원본, Rust 소스, 기존 ORDER와 인수인계의 근거를 함께 추적한다. 이 문서는 전체 기능 완료 선언이 아니다. 처음으로 돌아가 같은 메뉴 키보드 기능을 다시 구현하지 않는다.

원본 기능 목록은 [menu_cases.py](menu_cases.py)에 있다. 현재 기능 86행을 조사·열기·저장·닫기, 편집과 데이터 보존, 우클릭·키보드, 도면·내보내기, 홈, 정합과 자료 받기로 나눈다. 지도·레이어 우클릭의 이름 있는 동작 44개는 하위·동적 항목을 따로 추적한다. 조건·선택·활성화·취소·복귀와 남은 작업을 각 행에 기록한다. 파일 첫 줄을 가리키는 **검증 안 됨** 행의 참조는 조사 시작점이며 기능 동일성의 증거가 아니다.

전체 표시 목록과 분류 대기 목록은 다음 명령으로 현재 소스에서 재생성한다.

```powershell
python -m unittest discover -s scripts -p test_menu_audit.py
python scripts/menu_audit.py --write
python scripts/menu_audit.py
```

출력은 저장소에서 무시하는 `.codex/team/menu-audit/`에 보관한다. 생성한 보고서와 화면 PNG는 커밋하지 않는다. 다음 PC에서도 `docs/HANDOVER.md`의 C++ 참조 체크아웃을 준비한 뒤 같은 명령으로 만든다.

| 파일 | 용도 |
|---|---|
| `CURRENT_MENU_AUDIT.md` | 현재 86행의 조건·판정·증거와 과거 조사 484행의 재대조 대기 목록 |
| `PENDING_CPP_CONTROLS.md` | C++ 조작 선언 각각의 원본 위치·표시 문자열·연결 기능 또는 분류 대기 상태 |
| `menu_sources.json` | 파일 해시, C++ 참조 커밋, 앱 소스 트리, 모든 발견 후보와 미분류 항목 |

과거 484행은 [MORE0](../more/MORE0.md), [MENU0](MENU0.md), [EDIT0](../edit/EDIT0.md), [SHEET0](../sheet/SHEET0.md), [ALIGN0](../align/ALIGN0.md), [CADMENU0](../cadastral/CADMENU0.md)에서 이어받았다. 과거의 SAME·FAKE·MISSING 판정을 현재 판정으로 옮기지 않는다. 중복 별칭과 동적 항목은 분류할 때 정리하되 원래 행과 근거 연결을 남긴다.

## 판정과 증거

| 상태 | 기준 |
|---|---|
| 완료 | 그 행에 명시한 조건과 복귀 동작을 생산 UI 경로에서 확인했고 남은 작업이 없음. 근거를 읽은 소스 해시를 고정함 |
| 부분 구현 | 연결된 구현과 검증 근거가 있으나 명시한 누락·불일치·미검증 분기가 남음 |
| 미구현 | 해당 경로가 비어 있거나 연결되지 않았다는 현재 소스 근거가 있음 |
| 검증 안 됨 | 현재 구현·원본 계약·실행 근거가 충분하지 않음. 검색 실패만으로 미구현으로 바꾸지 않음 |

완료 판정은 해당 행의 좁고 명시적인 조건에서 실제 작동을 확인했다는 뜻이다. 검사한 레이어·작은 리본 메뉴의 Esc 소유권, 자석 대상 팝업의 선택 유지, MENU6의 작성 중 도형 보호, MENU7의 기존 선택 자료·이력 보호를 구분한다. 기존 `popup_escape_` 12개, MENU6 편집 키 6개, MENU7 선택 삭제 6개·이력 3개를 기존 입력 검사에 연결했다. 임시 데모 사본의 실제 egui 화면 PNG도 확인했다. OS 입력 주입과 새 창을 쓰지 않은 생산 UI의 headless 실행이며, 네이티브 창·실제 사이트·인쇄기 검증으로 확대하지 않는다. 전체 메뉴의 모든 키·포커스·조건을 완료로 묶지 않는다. 부분 구현은 연결된 코드와 일부 근거가 있어도 남은 동작을 완료로 볼 수 없다는 뜻이며, 검증 안 됨은 미검증이다.

목록 검사는 소스·근거 파일의 존재, 중복 ID, 완료 행의 실행 근거 종류·남은 작업·소스 변경을 검사한다. 이 형식 검사는 그 자체로 UI 동작 증명이 아니다. 소스가 바뀌면 완료 행을 재검증하거나 미검증으로 낮춘다. 해시를 자동 갱신해 오래된 완료 판정을 통과시키지 않는다.

## 기존 점검과 다음 우선 작업

- MENU1: 이름 있는 레이어 세트의 저장·덮어쓰기·적용·삭제와 명시적 저장 경계. 전체 도면 보관과 QGZ 가져오기는 별도 항목이다.
- MENU2: 레이어 우클릭의 경계·긴 이름·하위 메뉴 이동. 별도 지도 우클릭은 완료에 포함하지 않는다.
- MENU3·MENU4·MENU5: 앱 팝업, 기본 메뉴, 자석 대상 팝업의 Esc. 이번 목록은 기존 코드와 검사를 연결했으며 같은 기능을 재구현하지 않았다.
- MENU6: 레이어·기록 메뉴와 자석 대상 팝업이 열린 동안 Delete·Backspace·Enter가 작성 중 도형을 바꾸던 문제를 재현했다. 기존 대기 입력 경로를 확장했고 실제 검색칸의 포커스 보호는 유지했다. 선택된 기존 도형·레이어·정합점·도면의 삭제는 별도 검증 항목이다.
- MENU7: 기본 레이어 메뉴·레이어 우클릭 뒤에서 기존 도형·레이어·꼭짓점과 이력이 바뀌던 문제를 재현했다. 실제 범례 클릭과 피처 ID 선택 고정물, 저장 전 속성, 닫은 뒤 정상 편집·이력 및 파일 바이트 보존을 검사했다. 복합 입력의 한 번 편집·취소 우선·삭제 뒤 복원도 확인했다. 정합·도면·다른 메뉴와 입력칸 전체는 별도다.
- SNAP1A·SNAP1B: 백그라운드용 자료 소유권과 기존 스냅 명령의 CRS 오류 거부. 실제 캡처의 스냅 연결은 아직 없다.
- UI1~UI6: 옛 지도 선택, 도면 범례, 인쇄 탭, 래스터 정합, 홈 탐색기와 공통 반응형 표시. 각 기능의 남은 분기를 현재 목록에서 다시 구분한다.

다음 우선 대상은 **정합·도면의 Delete·Backspace와 다른 메뉴·입력칸의 편집·이력 소유권**이다. MENU6·MENU7 검사와 기존 포커스 고정물을 재사용한다. 새 조사·열기·저장 실패 시 원본과 미저장 변경 보존도 최우선으로 유지한다. 그 다음 실제 캡처 스냅, 파일·내보내기 경로와 미분류 우클릭·하위 메뉴를 순차 처리한다. 우클릭의 `layer.clear`와 `layer.export`는 현재 명시적으로 비활성인 미구현 진입점이며, 상위 내보내기 전체가 미구현이라는 뜻은 아니다.

선택한 소스 범위에서 발견한 조작 선언과 한국어 문자열은 모두 연결 또는 미분류 큐에 남기지만, 이는 의미별 기능 목록의 완전성을 증명하지 않는다. 범위는 C++ `src`의 `.cpp`·`.h`와 Rust `crates`의 `.rs`다. 이름에 test가 들어간 파일도 해시와 제외 이유를 남긴다. 동적 생성·사용자 자료별 항목·새 생성 함수·외부 UI 자원의 의미를 모두 검토하기 전까지 **전체 메뉴 대조는 진행 중**이다. 원본 선언 수, 파일 수와 문자열 수를 기능 수 또는 완료율로 사용하지 않는다.

## CI와 배포의 구분

기초 앱 커밋 `31a2600b7ef20d9ad491f767f550148016edda0f`의 [CI](https://github.com/kesekikwon-netizen/hgis-rust/actions/runs/44124055946)는 exact HEAD와 세 작업 모두 성공을 확인했다. 그다음 목록·도구 커밋 `a753e45`의 [CI](https://github.com/kesekikwon-netizen/hgis-rust/actions/runs/44131997603)는 별도로 추적한다. MENU6은 앱 입력 소스를 바꾸므로 이 두 결과를 새 커밋의 CI 성공으로 대신하지 않는다. 커밋별 로컬 검사, 실행 파일 교체, 원격 CI 상태를 각각 기록하며 실행 중인 작업을 완료로 표시하지 않는다.
