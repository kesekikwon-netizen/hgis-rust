## 2. The two checks

### (a) Does any Rust code send the password in an HTTP request?

No.

- `run_curl` (`strata-net/src/heritage_http.rs:39-87`) sends: `-sS`, `--max-time 30`, method, `-A <UA>`, the five fixed headers of `request_headers()` (`heritage_flow.rs:78-92`: Content-Type, UA, Accept, `X-Requested-With`, Referer), optionally `-b/-c <jar>`, optionally `--data-binary <body>`. The only bodies built anywhere are the list seed `pageMenuId=DAT010010&pageIndex=1` (`heritage_flow.rs:71-73`) and the search body made from the form's own fields plus the chosen 시·도/시·군 values (`heritage_flow_body.rs:12-50`). No code reads an account and puts it in a body, header or URL. The curl path never logs in at all: it assumes a cookie jar that nothing creates (every `cookie_jar` argument is `None` in the tests, `heritage_intranet_tests_flow.rs:93-104`; no non-test caller of `heritage_http_search`/`search_region`/`fetch_download_form`).
- The test URL with `pwd=` (`strata-net/src/heritage_intranet_tests.rs:14-19`) is only the **input string** of `redact_request_line` (`heritage_flow_script.rs:38-51`); the test asserts the output is `POST <로그인 요청 — 내용을 남기지 않음>`. Nothing is sent. The redaction rule equals `HIF:538-549` (login-like paths lose address and query; other lines keep the path and up to 400 characters of query).
- What the Rust login code does: `login_script` (`heritage_flow_script.rs:8-19`) builds a JavaScript text that sets `#userId` and `#pwd` to JSON-quoted values and calls `goLogin()` — i.e. fill the page and call the site's function, as the C++ does. It is wrapped in a plan (`tile_dispatcher.rs:60-76`) that no code executes.
- Two notes for the build: (1) the script text contains the password; the run host must never log it (C++ logs only the result, `KHB:658-665`). (2) A curl cookie jar (`-b/-c`) would write the session cookie to a file; C++ forbids a stored login (`NoPersistentCookies`, `KHB:306-308`). The browser route must keep the session in the incognito view only (`view.rs:105`).

The fallback `config/heritage-local.ini` was not looked for.
